Linux

The /proc-first resolver

The guide treats Linux the same as macOS, but Linux containers often lack lsof. The /proc-first resolver ensures native performance in Docker/Alpine without external dependencies.

import fs from 'fs';

export function resolveLinuxPids(port) {
  // Read /proc/net/tcp and parse hex ports
  const tcpFile = fs.readFileSync('/proc/net/tcp', 'utf-8');
  const lines = tcpFile.split('\n').slice(1);
  const pids = new Set();
  
  for (const line of lines) {
    if (!line.trim()) continue;
    // Implementation logic to match port...
  }
  return Array.from(pids);
}
Windows

PowerShell over wmic

wmic is disabled by default in newer Windows 11 builds, causing silent failures. PowerShell's Get-NetTCPConnection and Get-Process provide a robust alternative.

import { execSync } from 'child_process';

export function resolveWindowsPids(port) {
  try {
    const cmd = `Get-NetTCPConnection -LocalPort ${port} | Select-Object -ExpandProperty OwningProcess`;
    const output = execSync(`powershell -NoProfile -Command "${cmd}"`);
    return output.toString().trim().split('\n').filter(Boolean);
  } catch (error) {
    return [];
  }
}

Classifier Fallthrough Fix

If metadata lookup fails due to permissions, the classifier previously fell through to safety: 'safe'. Unknown metadata should explicitly mean unknown risk.

export function classifyProcess(metadata) {
  // FIXED Logical Hole

      reason: 'Permissions restricted or metadata unavailable'

Feature

The --tree Flag

Watcher-based port occupancy (nodemon, vite, dotnet watch) is the dominant real-world case. The --tree flag kills the entire process group, preventing lingering child processes.

export function killProcessTree(pid) {
  try {
    // On Unix, pass negative PID to signal the entire process group
    process.kill(-pid, 'SIGTERM'); 
  } catch (e) {
    if (e.code === 'ESRCH') return; // Process already dead
    // Fallback: manually transverse children and kill
  }
}
